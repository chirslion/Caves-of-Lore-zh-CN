tools/ —— 脚本命名与职责（本工程实际构成）
================================================

  生成汉化文件.bat   ★ Windows 双击入口（4 步全跑：build → b7 → b8 → verify）
  build_game.py      按 refer/ 生成 game/loc_files（43 个游戏文件）+ 字体合并 + DLL 登记
  b7_fix.py          按钮贴图重绘（像素字体原生 12px；图集格逐格 ROI）
  b8_fontsize.py     按钮文字排版统一（固定字号 / 文本框展宽加高）
  verify_build.py    产物校验（白名单对象 diff / CN 读回 / 存档类文件扫描）
  collect_md5.py     全量 md5 清单（双轮可复现性对比）
  pack.py            打包两类发布包（output/ 顶层 zip）+ 打包后清空 game/
  cold_test.py       冷缓存验收（沙盒安装 / 卸载全流程自证）
  game_config.py     路径与指纹配置（集中配置；路径不要散落在各脚本里）
  col_lib.py         裸解析 / 重建（对象级字节保真）
  col_schemas.py     各类 Mono 数据的字段 schema
  font_tool.py       字体子集化与按 '0' 基准合并
  prebuilt/          预编译补丁件（补丁版 DLL / CavesL10N / 表 / 词表；工程包复现用）

================================================================
pack.py 的两类产出（硬性要求，直接产在 output/ 顶层 = 仓库根）：

  1. **玩家包**  Caves of Lore 简中汉化包 v1.0（玩家版）.zip
     43 个搬运式游戏文件 + 安装.bat / 卸载.bat / 说明.txt / 术语说明.txt
     （bat 与说明由 pack.py 生成，玩家侧不需要 Python）。解压到游戏目录或
     与其同级，双击 安装.bat 即可；卸载双击 卸载.bat，从 *.l10nbak 还原。
  2. **工程包**  Caves of Lore 简中汉化工程 v1.0（工程版）.zip
     output/ 内容快照：README + refer + tools + fonts + 安装说明 + 提示词；
     origin/ 与 game/ 均为空占位（仅 说明.txt）。收件人把原版游戏放进 origin/，
     双击 tools/生成汉化文件.bat 即可逐字节复现全部产物。

打包后必须复查：
  · 两个包都不得出现 SAVEGAME / StreamingAssets / .log / *.l10nbak；
  · 工程包不含游戏本体与生成物；玩家包不含 refer/、tools/、workspace/；
  · 打包完成后 game/ 自动清空为占位（仅 说明.txt）——生成物只进玩家包、不进仓库；
  · **不建 交付/ 目录、不保留解压副本**（两个 zip 由内存直接写盘）。

注意（2026-10-17 新基线）：**pack.py 需要的源文件必须全部位于 output/ 内**
（refer/、tools/、fonts/、prebuilt/、README.md 等）。项目根 workspace/、docs/、test/
既不进 GitHub 仓库（仓库根 = output/），也不进工程包。

================================================================
bat 规范（实测教训）：

  1. 编码用 GBK，**不要** `chcp 65001`（中文 Windows 下消息/文件名才正确）；
  2. bat 内引用的**文件名一律 ASCII**（GBK bat 引用中文文件名会匹配失败，
     ——写死中文**目录名**做 `if exist` 判断同样会匹配失败，路径一律从 `%~dp0` 拼）；
  3. `if (...)` 块内的 echo 消息避免**半角括号**（cmd 会当块结束符报错）；
  4. 大文件追加补丁用 `type 补丁.bin >> 目标文件`（逐字节无损）；
  5. 备份来源必须可靠 —— **「搬运式」**（汉化文件放 `game/loc_files/` 内层，
     复制到游戏目录不覆盖原文件）让安装.bat 在覆盖前拿到的一定是原版，
     于是**不需要随包附带原版**；只有"追加式"修改（无法就地备份的大文件）
     才随包附带 `.original`；
  6. bat 内置**制作基准的版本号 + 原始文件尺寸校验**，不符即中文报错、一个字节都不写；
     若补丁是**逐字节等长改写**（改后尺寸不变），"装没装过"要用**别的**尺寸判据
     （如被追加数据的那个大文件的尺寸）；
  7. 写入顺序：**指向追加数据的索引文件要最后写**，中途失败也不影响游戏启动；
  8. 不要用编辑器对 GBK 的 bat 做局部文本替换（按 UTF-8 回写会把中文写坏），
     要改就整体重写后转 GBK（本工程用 python 以 gbk 读写）。

缺游戏文件 / 缺依赖时，一律输出**中文操作指引**，不要堆栈。
